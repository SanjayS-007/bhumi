## The real-document findings (see docs/REAL_DOC_FINDINGS.md for full detail)

- Fully born-digital, 254/254 pages — Tier 1 alone handles it; Tier 2 was
  never invoked.
- Real spanning headers put text once, in the leftmost cell, `None`
  elsewhere — the opposite of this codebase's own synthetic convention.
  Fixed `resolve_headers()` to use real per-cell bbox geometry instead of
  guessing. Verified on the actual 3-level ragged header from page 18/19 of
  the real GR (reconstructed correctly for all 17 columns).
- Real cell text embeds literal `\n` at line-wrap points (e.g. `"CSM
  \nI&II-01"`) — fixed by collapsing whitespace on every extracted cell,
  not just header text.
- A seam's real data spans **two grid rows** (values row + a borehole-
  reference row) — not designed for, but the per-row emission model
  degrades safely: the reference row soft-rejects for a missing entity
  rather than crashing or fabricating a record. Named gap, not fixed.
- **The document is classified `restricted`** (internal-distribution-only
  banner on page 1) despite the URL being public. Registered accordingly;
  never committed to the repo.

## Severity decisions and rationale (warn vs block)

| Rule | Severity | Why |
|---|---|---|
| `thickness_range` | block | A seam thickness outside 0-50m is not a real geological finding on this dataset — near-certainly an extraction error. |
| `pct_range` | block | A percentage outside 0-100 is definitionally wrong, not a judgment call. |
| `net_le_gross` | block | Net/effective thickness excludes partings within the gross seam by definition; a violation is essentially always a transcription/OCR error. |
| `ash_gcv_inverse` | **warn** | A heuristic prior, not a physical law — geology has genuine exceptions. Blocking would make the system unusable and wrongly annoy a geologist on a legitimate edge case. |

## Confidence distribution, before and after the §1.1 fix

- **Sample doc, before fix:** the one extracted table scored `0.667` —
  below the 0.80 floor, landed in `review_queue` — purely because the
  page's prose-density-based quality score penalized a table-dense page.
- **Sample doc, after fix:** same table, `0.95` (weakest of: tier prior
  0.95, grid consistency 1.0, header-resolved 1.0 for every cell). Review
  queue empty.
- **Real GR (pages 14-19), after fix:** the two classified tables (p18,
  p19) both scored `0.95`. Cell-level Assay confidence naturally lands
  lower for some candidates (e.g. `0.6` when a metric falls back to a
  rulebook-default unit) — that's the Assay's job, not the read pipeline's.

## The reeval demo, run for real (not simulated)

1. With the pack's borehole regex not yet accepting `.` as a separator,
   `SKM.18`'s 5 metric candidates soft-rejected at G2 (missing entity).
2. Widened the regex (`domain/packs/geological_report.yaml` v2→v3),
   documented the change in the pack file itself and in PROVENANCE.md.
3. `task assay reeval --reason "domain pack v3: borehole ID separator
   widened to accept '.'" --doc-id SAMPLE-MARWATOLA-G2`:
   ```
   re-evaluating 6 soft_rejected candidates
     5 now pass -> pending_review or auto_passed
     1 still soft_rejected
   ```
   The 1 unchanged is the physically-impossible rule violation — correctly
   untouched by a pack change. `tests/test_reeval.py` also proves reeval
   never touches an already-`published` row.

Two real bugs were found and fixed while building this demo, not before:
`entity_raw` was silently dropped to `""` on failed resolution (making
recovery structurally impossible), and the pair-rule evaluator only loaded
`soft_rejected` rows, so a rejected candidate's passing sibling was
invisible and the pair check silently "recovered" something that should
have stayed rejected. Both are in PROVENANCE.md with the fix.

## Known issues, with severity

- **High** — real seam records spanning two grid rows aren't structurally
  captured (borehole-reference row is discarded, safely). Blocks a genuine
  "per-borehole" fact story on this document until fixed.
- **Medium** — multi-page table continuation unverified; could silently
  produce two disconnected `TableElement`s for one real table.
- **Medium** — this machine's permanent `UV_PROJECT_ENVIRONMENT` means
  `doctor --strict` (and by extension `task verify`) will report failure
  here until the user fixes their own shell environment. Not a code bug.
- **Low** — unit extraction from non-parenthesized headers (`"k. cal/kg"`)
  falls back to a rulebook default rather than truly reading the unit;
  works, but isn't the "unit was read, not guessed" story for that metric.
- **Low** — footnote-marker *detection* is unverified against a real
  footnote (only against the synthetic sample's).
