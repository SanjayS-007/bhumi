Fixed via `--basetemp=.pytest_tmp` in `pyproject.toml`'s `[tool.pytest.ini_options]`, gitignored. `task test`/`task verify` need no manual flag; a bare `pytest` outside taskipy would need the same.
- **2026-09-04** — Ruff's default (aggressive) rule selection was narrowed to `E,F,W` with `E501`/`E741` ignored. Reason: `BBox` fields are named `l/t/r/b` to mirror the design doc's schema exactly (ruff's E741 flags `l` as an ambiguous name); several long f-string log/UI lines are more readable unwrapped. `F` (undefined names, unused imports — real bugs) stays strict.
- **2026-09-04** — `TableCell.bbox` comes from PyMuPDF's `table.rows[r].cells[c]` (verified empirically — this attribute is not documented prominently but returns per-cell `(x0,y0,x1,y1)` tuples in exact row/col order matching `table.extract()`). - **2026-09-04** — Header-chain resolution (`read/headers.py`) assumes spanning headers repeat their text in every spanned column (rather than leaving blanks). This is a convention *this codebase's own sample generator follows*, not a universal PyMuPDF behavior — a real scanned/born-digital GR's multi-level headers may not repeat text this way, and `resolve_headers()` has not been tested against one. Flagged in `ENVIRONMENT_REPORT.md`-adjacent honesty: don't claim this resolver works on real GRs until tested against one.

## MVP-1.5 / MVP-2 session (2026-09-05)

- **Real GR acquired**: `MARWATOLA_I&II_G2.pdf`, fetched from the exact NMET URL the design doc named. Confirmed the previous entry's flagged risk was correct: real spanning headers repeat text **nowhere** — text sits once in the leftmost spanned cell, everything else is a true blank. `resolve_headers()` was rewritten to use real per-cell bbox geometry (bbox-containment fallback) instead of guessing from text position. Both conventions verified working (`tests/test_headers.py`). Full findings: `docs/REAL_DOC_FINDINGS.md`.
- **This document is classified `restricted`, not `public`**, despite being fetched from a public government URL — page 1 carries an explicit internal-distribution-only banner. Registered accordingly. The design doc's "publicly downloadable" description refers to URL reachability, not the document's actual classification; don't conflate the two for any future document either.
- **curl/TLS on this machine**: plain `curl https://nmet.gov.in` fails with `CRYPT_E_REVOCATION_OFFLINE` (OCSP/CRL check can't complete) even though `https://pypi.org` works fine. Fixed per-request with `--ssl-no-revoke`. This is host/network-policy specific — don't assume it generalizes to other `.gov.in` domains or other machines.
- **Confidence model bug fixed**: page-level `quality_score` (routing) was conflated with cell-level extraction confidence, so a clean born-digital *table-dense* page scored low purely for having little prose. Split into `classifier.PageProfile.quality_score` (routing only, now `1.0` for any born-digital page) and `read/confidence.ElementConfidence` (weakest-link over tier prior, grid consistency, and per-cell header-chain resolvability). Verified: the sample doc's review queue is now empty; `tests/test_review_queue.py` keeps the mechanism exercised via a genuinely blank-page fixture instead.
- **Alembic wired up for real** (`alembic/`, autogenerated initial revision, `render_as_batch=True`). `storage/db/engine.migrate()` now runs `alembic upgrade head` instead of `create_all()`. `alembic/env.py` only falls back to `get_settings()` for its DB URL if the caller (`engine.migrate()`) hasn't already set one — needed so tests using a `tmp_path`-scoped `Settings` object actually migrate their own isolated DB, not the process-wide one.
- **`UV_PROJECT_ENVIRONMENT` guard encoded, not just documented**: `env/probe.py::probe_uv_project_environment()` checks it points inside this repo; `doctor --strict` now fails if not; `bootstrap.ps1` checks and exits before touching anything. **This machine has it permanently set at the user/OS level** to `C:\dev\src\cne-platform-venv` (confirmed: persists across fresh shell invocations, not something this session set) — meaning `uv run task doctor --strict` will genuinely fail on this specific machine until the user unsets it themselves or scopes it away from this repo. This is a real, standing condition of this machine, not a bug introduced this session — do not "fix" it by weakening the check.
- **Real bug — `register_local_file` couldn't handle re-registering the same `doc_id` with changed content** (a new sha256, e.g. from editing `make_sample_pdf.py`): hit the `doc_id` UNIQUE constraint. Fixed: look up by `doc_id` first and replace the row if the artifact_id differs.
- **Real bug — `CandidateFact.entity_raw` was silently dropped to `""` whenever entity resolution failed**, making a soft-rejected candidate permanently unrecoverable by any later pack fix (reeval has nothing to re-attempt resolution against). Fixed in `domain/emit.py` to always carry the original cell text.
- **Real bug — `assay/reeval.py` initially only loaded `soft_rejected` rows before evaluating pair rules** (e.g. `net_le_gross`), so a rejected candidate's *passing* sibling (e.g. its `gross` counterpart) wasn't visible, and the pair check silently found nothing to compare against — incorrectly "recovering" a candidate that should have stayed rejected. Fixed: pair/range findings are computed over every candidate for the doc; only rows that were actually `soft_rejected` get a new state written.
- **Domain pack rebuilt around real structure**: added `seam_range_summary_table` (Min/Max per seam, matching the real GR) alongside the original `seam_thickness_table` (kept explicitly labeled as modeling only this codebase's synthetic sample — no real document has ever matched it, confirmed by exhaustive search). Borehole entity regex updated to the real `CSM I&II-NN` / `MSM-NN` series; `SKM`/`SGT` kept only for the synthetic sample.
- **New real-world gap found and NOT fixed this session (documented, not silently assumed away)**: a seam's data in the real range-summary table spans two grid rows (values row + a borehole-reference row) — see `docs/REAL_DOC_FINDINGS.md` §9. The per-row emission model degrades safely (the reference row soft-rejects for missing entity, doesn't crash or fabricate), but the borehole-reference information itself isn't captured as structured data. Left as a named Phase-3 enhancement, not implemented.
- **Multi-page table continuation is unverified** for this document's borehole lithology logs — each page is processed independently; a table spanning a page break would silently become two unlinked `TableElement`s. Not investigated this session; flagged in `docs/REAL_DOC_FINDINGS.md`, not fixed.

## MVP-2.5 + MVP-3 session (2026-09-06)

- **Multi-row range gap: diagnosed then fixed for real**, not guessed at. The prior "safely degrades" note undersold what was actually happening: the borehole-reference continuation row was independently emitting *garbage* candidates (a borehole-ID string like `"MSM-55"` as a fake numeric `value_raw` for a thickness column), which happened to soft-reject only because its identity column was blank — not because anything detected it as a reference row. Fixed with a minimal row-group / `blank_continuation` detector in `domain/emit.py`; the continuation row's borehole mentions are now captured as a `source_boreholes` qualifier on the owning row instead of being discarded or misused. `CandidateFact.value_kind` (`point`/`min`/`max`) replaces the ad-hoc `qualifiers["stat"]`.
- **Real bug found while fixing the above**: stale `candidate_fact` rows from before the fix weren't pruned — a (row,col) position that stops being emitted leaves its old DB row behind forever. Fixed in `assay/pipeline.py::run_assay`: prune rows no longer emitted, **except** any a human has already decided (`published`/`rejected`) — those are never touched regardless of what the emitter does later.
- **Multi-page continuation: verified REAL, not just theoretically possible.** Pages 15-17 (1-indexed) of the real GR share an identical header row and are one logical table split by two page breaks — confirmed by direct header comparison. Implemented the real fix (`read/continuation.py`, `repeated_header` signal only — the only signal actually observed; `caption_continued` and `page_boundary_row_match` were not implemented since no real example of either was found). Verified: re-ingesting merges the 3 pages into one 98-row table.
- **Classification decision recorded and enforced in code**: `docs/CLASSIFICATION_DECISION.md`. The Marwatola GR is `restricted` because the document's own page 1 says so explicitly — not a coordinates/estimates judgment call. "Publicly downloadable" (NMET's hosting) and "classification: public" are stated as *not the same judgment*. `export/guard.py::assert_exportable` raises `ExportBlocked` for any non-public document; wired nowhere else yet (no video/export pipeline exists to wire it into besides its own tests) but ready.
- **A second, unambiguously public document was acquired**: the NMET GR submission format spec (8-page procedural template, scanned for restriction language — none found). Registered `--classification public`.
- **huggingface.co is blocked at the network/proxy level on this machine** — confirmed via raw HTTP request (HTTP 403 on the bare domain, not an API/auth error). This means embeddings and the entailment checker are genuinely CPU-viable per the design doc but **cannot actually be fetched here** — a network policy, not a capability gap. `env/probe.py::probe_huggingface_reachable` reports this honestly rather than silently marking them "unverified" for the wrong reason. Fixed the *unrelated* SSL cert-chain error (`CERTIFICATE_VERIFY_FAILED`) along the way by installing `pip-system-certs` into the venv only (not a tracked project dependency) so Python uses the Windows trust store like `curl`/schannel already does — that was a real, separate, legitimately-fixable issue; the network block is not.
- **Entailment checker (MiniCheck-Flan-T5-Large, ~3GB) deliberately never fetched on this machine**, per explicit user instruction this session — independent of the network block above. `config/models.yaml` keeps the entry (needed on the workstation); `scripts/fetch_models.py` respects `BHUMI_SKIP_MODELS` to enforce this without deleting anything a workstation clone needs.
- **Profile auto-detection added** (`config/settings.py::resolve_profile_with_reason`): `BHUMI_PROFILE` env var is an explicit override that always wins; otherwise CUDA presence → `workstation`, else `BHUMI_POSTGRES_URL` set → `supabase`, else `sqlite`. Printed with its reasoning by `task profile`, never a silent guess.
- **Tier 3 (PaddleOCR-VL) now has a real implementation**, not a bare `NotImplementedError` — gated by a real capability check (llama-cpp-python importable, CUDA present, GGUF weights on disk). Its actual llama.cpp multimodal call shape is **unverified by execution** (no GPU here) and explicitly flagged as such in the module docstring — verify the exact API against the installed version before trusting it on the workstation. `@pytest.mark.requires_gpu` tests exist and auto-skip without CUDA (`tests/conftest.py`), rather than being silently absent.
